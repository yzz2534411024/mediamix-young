# CatVideo 前端重构方案

> 基于 2026-10-02 对现有 UI 代码的实测诊断。**只重构视觉与交互层**，不动数据/播放引擎/导航结构。

## 一、诊断：为什么"不好看"

对 `composeUi` 全量扫描的客观结果：

| 维度 | 现状 | 问题 |
|---|---|---|
| **品牌色** | `Color.kt` 用的是 Material 3 脚手架默认紫色 seed `#6750A4` | 与应用图标（蓝渐变 + 白猫 + 淡粉耳）完全无关，没有品牌识别 |
| **排版** | `Typography.kt` 全文 5 行：`val Typography = Typography()` | **零设计** —— 所有文字都用默认字号/字重，标题与正文拉不开层次 |
| **形状/间距** | 无自定义 Shape、无间距常量 | 各处 `.dp` 随手写，同层级元素间距不一致 |
| **硬编码颜色** | **39 处** `Color(0xFF…)` 直接写在组件里 | 无法统一换肤，深色模式必然有漏网 |
| **动画** | `AnimatedVisibility` **0 处**、`Crossfade` **0**、`spring` **0**、`animateContentSize` **0**、`animateFloatAsState` 1 | **几乎没有任何动效** —— 点击、切页、展开全是硬跳，"廉价感"的主要来源 |
| **组件化** | `components/` 只有 6 个文件 | 卡片/区块头/空态/徽章等在各页面重复实现，风格漂移 |
| **巨石页面** | `PlayerScreen.kt` 893 行、`VideoHomeScreen.kt` 777 行 | 一处改动牵一发动全身 |

**结论**：不是"配色丑"，是**没有设计系统**。修法不是逐页调色，而是先立 Token 与组件，再让页面去消费。

## 二、设计 Token 体系（可直接落地）

### 2.1 配色 —— 从应用图标反推品牌色

图标是「蓝渐变底 + 白猫 + 淡粉耳」，主题色直接沿用这套色，视觉才自洽：

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `primary` | `#2D6BF5` | `#5B8DFF` | 主操作、选中态、链接 |
| `onPrimary` | `#FFFFFF` | `#0A1428` | 主色上的文字 |
| `primaryContainer` | `#E3ECFF` | `#1B2A4A` | 主色浅底（Chip 选中、卡片高亮） |
| `accent` | `#FFC4D6` | `#FFB3CB` | **情感动作**：收藏、点赞、成就 |
| `background` | `#F7F8FB` | `#101216` | 页面底 |
| `surface` | `#FFFFFF` | `#171A20` | 卡片、弹窗 |
| `surfaceVariant` | `#EEF1F6` | `#1F232B` | 次级容器、输入框 |
| `textPrimary` | `#10131A` | `#F2F4F8` | 标题、正文 |
| `textSecondary` | `#5B6472` | `#A8B0BD` | 辅助说明 |
| `outline` | `#DFE4EC` | `#2A2F38` | 分隔线、边框 |
| `success/warning/error` | `#2E9E6B` / `#E8A33D` / `#E5484D` | 同色提亮 | 状态语义 |

**规则**：组件里**禁止出现 `Color(0xFF…)`**，一律走 `MaterialTheme.colorScheme.*` 或扩展 Token（`LocalCatColors`）。

### 2.2 排版阶梯（当前完全缺失）

| Token | 字号/字重 | 行高 | 用途 |
|---|---|---|---|
| `displayTitle` | 28sp / 600 | 34 | 详情页片名 |
| `titleL` | 22sp / 600 | 28 | 区块标题（"继续观看"） |
| `titleM` | 17sp / 600 | 24 | 卡片标题、页面标题 |
| `body` | 14sp / 400 | 20 | 正文、简介 |
| `label` | 13sp / 500 | 18 | 按钮、Chip、标签 |
| `caption` | 12sp / 400 | 16 | 集数、时长、次要信息 |

**原则**：一屏内最多出现 3 个层级；强调用**字重和颜色**，不用放大字号。

### 2.3 间距 / 圆角 / 层次

- **间距**：只用 `4 / 8 / 12 / 16 / 20 / 24 / 32`（4 的倍数），定义 `Spacing` 对象
- **圆角**：海报 `8`、卡片 `12`、按钮 `10`、Chip `999`、弹窗 `20`
- **层次**：0 平面 / 1 卡片(2dp) / 2 悬浮(8dp) / 3 弹窗(24dp) —— 靠**描边 + 极浅阴影**表达，不用重阴影

## 三、动效规范（当前为零，收益最大）

统一时长与缓动，让"感觉"一致：

| 场景 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| 按钮按下 / 图标切换 | 120ms | easeOut | 缩放 0.96 + 透明度 |
| 选中态 / Chip 切换 | 180ms | FastOutSlowIn | 颜色 + 尺寸 |
| 页面转场（前进/返回） | 260ms | FastOutSlowIn | 位移 24dp + 淡入，返回反向 |
| 列表首屏入场 | 240ms | easeOut | 卡片**错峰 25ms/项**，最多错峰前 8 项 |
| 播放控制栏显隐 | 200ms | easeOut | 透明度 + 上位移 12dp |
| 简介展开/收起 | 220ms | FastOutSlowIn | `animateContentSize` |
| 收藏心跳 | 420ms | spring(0.45) | 图标缩放 1 → 1.25 → 1 |
| 加载骨架 shimmer | 1200ms 循环 | Linear | 渐变色扫过，**替换现在的静态占位** |
| 下拉刷新 | 标准 | — | 用 `PullToRefreshBox` 统一 |

**约束**：动效服务于状态变化，不做装饰性动画；全部尊重系统「减少动态效果」开关。

## 四、统一组件库（12 个）

| 组件 | 职责 | 关键参数 |
|---|---|---|
| `PosterCard` | 首页/搜索/收藏网格卡片 | 2:3 比例、标题 1 行、角标（集数/更新） |
| `ContinueWatchingCard` | 历史横向条 | 带进度条叠加 |
| `SectionHeader` | 区块标题 + 更多入口 | title + action |
| `RatingBadge` | 评分/清晰度角标 | 半透明底 + 描边 |
| `CatChip` | 分类/选集/画质筛选 | 选中态走 primaryContainer |
| `EmptyState` | 空态（插画 + 主按钮） | 9 处空态统一 |
| `ErrorState` | 错误态 + 重试 | 复用现有 ErrorView 并升级 |
| `SkeletonGrid` | 骨架屏网格 | shimmer，替代 LoadingIndicator |
| `CatButton` | 主/次/文字三态按钮 | 统一高度 44、圆角 10、点击反馈 |
| `BottomSheetShell` | 选集/画质/倍速面板 | 统一把手、标题、内边距 |
| `GradientScrim` | 图片上文字可读性 | 底部渐变遮罩 |
| `IconAction` | 图标按钮 | 统一的点击区域与涟漪 |

**验收方式**：`DebugScreen` 加「组件预览」入口，所有组件在双主题下一屏可见 —— 改样式不用翻页面。

## 六、实施路线（按风险从低到高）

| 阶段 | 内容 | 产出与验收 |
|---|---|---|
| **S1 基建** | 落 Token（Color/Typography/Shape/Spacing）、消除 39 处硬编码、双主题对照 | 全局换肤生效；`grep Color(0xFF` = 0 |
| **S2 组件库** | 12 个组件 + 组件预览页 | 预览页双主题无异常 |
| **S3 逐页重构** | 首页 → 详情 → 播放 → 其余页面 | 每页单独提交、可回退；功能零回归（现有 583 项测试保持全绿） |
| **S4 动效精修** | 按第三章清单补齐动效 | 录屏对比；无掉帧（桌面 60fps / 移动端帧率不降） |

**播放页放最后**：手势层与控制层耦合最深，先在其他页面验证模式成熟再动它。

## 七、边界与风险

- **不改**：数据层、播放引擎、导航结构、`AppIcons`、平台抽象（expect/actual 契约）
- **主要风险**：播放页手势回归 → 保留现有 `GestureLayer` 契约，只换视觉皮肤
- **双端差异**：用 `maxWidth` 判断横竖屏与桌面/移动布局（沿用现有做法），不引入新框架
- **性能**：动效用 `graphicsLayer`/`animateFloatAsState`，避免整树重组；列表项 key 稳定

---

**建议开工顺序**：S1 + S2 一轮做完（一次交付即可看到整体的视觉跃迁），确认风格后再逐页推进。
